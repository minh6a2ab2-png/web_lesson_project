# Engine routing and acceptance
Priority: native/local with proven capability, supported connector, bounded public-only CI with approved inputs, compatible verified cache/alternative, one batched human fallback. Select by pedagogical fit, rights, availability and user effort. No repeated attempts to blocked network. Asset direct-link fallback: one HTML with per-image direct file links, source, rights and filename; download behavior may depend on server.
- Asset/Browser/Artifact: engines/ci/r02.py + pilot.py are verified bounded fixture, not a general source service. Source allowlist and contextual rights required per task; never distribute standalone Pexels stock archive. Browser fixture PASS != exact lesson QA; direct-render != file/localhost. Readback digest and safe ZIP validation; durable archive.
- Design: packs/design-contract-r02.json, INTEGRATION.md. Local DESIGN.md, visual intent and layouts complement canonical kinds; no upstream parser claim. Apply selected upstream design guidance, not default external runtime.
- Motion: engines/motion-engine.js, native CSS/WAAPI default. GSAP 3.13.0 synthetic runtime PASS, optional offline/license integration pending. Motion can be interrupted; no automatic learning state advancement, no mandatory wait. Preserve static information with reduced motion.
- Game: engines/game-engine-generalized.js validated logic; renderer remains activity-specific. Native Canvas and DOM labels, keyboard/touch, no navigation/score penalty for motor speed; alternative equivalent interaction. External sprite tools only if licensed and appropriate.
- Multimedia: FFmpeg/Pillow/eSpeak tested on R01 specific prototype; source prototype in private companion pack, not generic production engine. Media optional, no autoplay, captions/transcript/fallback, voice QA. Remotion, Meowa, Phaser, TTS advanced and other external tools on demand after permission/runtime/rights checks. No mandatory new dependencies.
- Orchestrator: engines/orchestrator.py single-writer local content-addressed cache, bounded retry, dependency planning; no full Skill scheduler or cross-workflow cache claim. Inputs include code identity, config, source/dependency hashes; verify outputs before reuse. See tools/plan_rc1.py for explicit approval and version bridge. No user credentials in logs.
All engines must report task ID, scope, tool version, input/output hashes, tests, status, issues, human steps. Native product HTML/CSS/JS offline; production tools may have dependencies but delivered lesson must not need build/CDN. Tests may run in approved private environment; public CI only public fixtures.
